# ppt-harness 改进方案（问题 → 方案 索引）

> 本文档汇总了针对 ppt-harness 历次反馈中提出的问题及其改进方案，按「反馈轮次」组织，每轮列出**问题 / 根因 / 方案 / 验证**。配套技术细节见 `ARCHITECTURE.md §11–§12.14`。
>
> 所有改进均**零新依赖**（用 Node 内置 fetch + 现有 harness），凭证复用宿主会话的 `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN`（本机即 GLM 兼容端点，自带服务端联网检索）。

## 第一轮：内容丰满 + 交互接口

### 问题 1.1 — PPT 内容不够丰满
**根因**：harness 原本是纯渲染/编译器，从不联网、不调 LLM，内容全靠外部 LLM 凭记忆写。
**方案**：新增「研究驱动生成」层——
- `lib/llm.js`：Anthropic 兼容端点（GLM）瘦客户端，支持服务端联网检索、严格 JSON、并发。
- `lib/research.js`：多角度并行检索（概况·数据·应用·趋势·案例·挑战）→ 聚合去重排序 → 研究简报（真实数字/案例/趋势/来源）。
- `lib/outline.js`：把简报编译成内容丰满的大纲（数字→stats、案例→table、趋势→future，来源写进 note）。
- `lib/orchestrator.js`：`generateDeck(topic)` 串起 research→outline→compile→validate→build。
**验证**：`固态电池技术` 9 内容页，stats 全为真实数字（5.3GWh→36GWh、65% 良率），table 列真实企业。

### 问题 1.2 — 缺一个交互接口
**方案**：`chat.js` REPL——`node chat.js`，自然语言提需求（"请帮我生成一个 X 的 ppt"），解析主题+修饰词（深色/极简/详细/不配图/创意…），支持追问（换主题/加一页/去配图/重新生成）与 `/help /research /outline /brief /quit`；`--once` 一次性模式。

## 第二轮：版式校验 + 自由版式 + 审查闭环（4 个问题）

### 问题 2.1 — 图片重复、内容越界
**方案**：① 每 deck 建 `img._used` 集合，`getImage({used})` 命中已用 URL 就换下一张；② `layout-qa` 的 bounds 检查，任何非装饰元素越出 `[0,13.33]×[0,7.5]` 即报错。

### 问题 2.2 — LLM 写完后无格式检查（覆盖/重叠/越界）
**方案**：**几何捕获层**——`build()` 把 `E` 原语包一层 recorder（`wrapElements`），不改渲染器、不改 elements.js，每个放置的元素按语义层级记一条 box。`lib/layout-qa.js` 的 `analyze` 做三类确定性检查：越界、重叠（容器↔容器 + 文字↔文字；文字压面板是刻意叠层不算冲突）、留白。chart/table 另在 slide 对象打补丁捕获。当场抓出并修了一个真 bug（agenda >6 节时溢出）。

### 问题 2.3 — 格式单调、要由 LLM 决定、harness 只提供工具
**方案**：**自由版式** `RENDERERS.free`（`lib/freeform.js`）——slide = `{t:'free', elements:[{k,x,y,w,h,…}]}`，10 种元素工具箱；harness 零版式决策，只渲染 + 校验。`lib/freeform-deck.js` 每页轮换不同构图原型，构图完全由 LLM 决定。

### 问题 2.4 — 严禁大片留白 + LLM 检查内容
**方案**：① 留白检测用**最大空白矩形**（非连通域外接框，避免误判）；② `lib/review.js` + `buildWithReview` 审查修订闭环：build→layout-qa→有问题交 LLM 重排/补内容→重渲染，循环 ≤3 轮直到干净。

## 第三轮：封面极简 + 对比度 + 浅色（2 个问题）

### 问题 3.1 — 封面信息过多
**方案**：封面用独立的"极简"系统提示——只放标题(+副标题+小字)，元素 ≤6，浅色背景，大量留白（封面豁免留白检查）。元素数从 26 → 5。

### 问题 3.2 — 对比度不够 + 少用深色
**方案**：① `lib/color.js`（WCAG 亮度/对比度）：freeform 渲染时追踪每个面板（z 序），对每个文字算出背后真实背景，对比度 <4.5 就自动改写为白/近黑——文字永远看不清的问题根治；② 默认浅色背景（结语不再用 `dark`；typed `closing` 渲染器从 `C.dark` 改为 offWhite）。

---

## 第四轮：标题一致 + 案例配图 + 留白收紧（3 个问题）

### 问题 4.1 — 每页标题格式不一致
**方案**：内容页用 `title`/`eyebrow`/`sub` **字段**（不是 element），`drawTitleBand` 在**每页顶部统一绘制**标题带（眉标+标题+副标题+强调线+页脚），全 deck 一致；内容元素限制在 `y∈[2.1,6.9]`。

### 问题 4.2 — 案例/举例缺图
**方案**：composer 硬性要求"含案例的页每个案例配 image；涉及产品/企业的页也要配图"；`detectImageLight` 检测缺图。

### 问题 4.3 — 留白（如 mRNA 第 4 页）
**方案**：留白阈值从 20%/1.3″ 收紧到 **14%/1.1″**（typed deck 仍 clean）。

---

## 第五轮：杜绝"大数字方格"（AI 感）

### 问题 5 — 满屏"大数字+一句话"方格
**方案**（三道防线）：① 删 `stat-dashboard` 原型，换 `data-story`（数字写进句子/图表）；② plan/compose 硬性禁止"数字+一句话独立方块"，数值序列用 chart/table；③ `detectStatTiles`——一页 ≥2 个大数字方格即报错，交修订闭环改写。

---

## 第六轮：块数约束 + 图片遮挡（2 个问题）

### 问题 6.1 — 块过多 / 小块堆砌
**方案**：`detectTooManyBlocks`——除 `card-grid`（合法列举）外，每页**大块面（≥2.5in²）≤3**；composer 要求"少数大块 + 文字/图标点缀，不要堆小方块"。

### 问题 6.2 — 图片被方框遮挡（看不见）
**方案**：`detectHiddenImages`——image 被它**之后**的不透明 rect/rrect 覆盖 ≥60%（图片在下层）即报错；修订把图片移到方框之后或删遮挡方框。

---

## 第七轮：并列块一致 + 块内饱满 + 回归护栏（2 个问题）

### 问题 7.1 — 并列块格式不统一
**方案**：`detectInconsistentBlocks`——同一行（y 重叠 ≥50%）≥2 个大块聚类，比较视觉特征（img/icon/无）与**填色类别**（见第九轮），不一致即报错；composer 要求"并列块结构完全一致"。

### 问题 7.2 — 块内内容偏少 / 框内留白（如 mRNA p4 ~39% 填充）
**方案**：`detectThinBlocks`——逐个大块估算内部文字**实际渲染高度**对比可用文字区，<50% 报"内容偏少"；composer 要求"每块描述 2-3 句或 3-5 条要点，撑满方框"。
**附带**：修订回归护栏 `countOverlaps`——修订若引入新重叠就**拒绝、保留原元素**（并注入标题带/页脚为合成框，捕捉"内容挤进标题带"），闭环永不把一页改差；`maxIters` 提到 3。

---

## 第八轮：图文并茂

### 问题 8 — 图片太少
**方案**：`detectImageLight`——内容页 0 图报"缺图"；并列 ≥2 大块但图片数 < 块数报"并列块未都配图"。composer 硬性要求"每页必配图，多块页每块/每案例各一张图，图片是版式主体"。实测各页配图从 `[0,0,0,4,0,0]` → `[3,2,3,3,2,3]`。

---

## 第九轮：默认微软雅黑 + 更有创意

### 问题 9.1 — 字体
**方案**：`lib/typography.js` 默认 headingFont/bodyFont 均改为 **`Microsoft YaHei`**（渲染后实测 116 处文字用雅黑）。

### 问题 9.2 — 排版不够有创意
**方案**：① 新增创意元素：`ghost`（淡淡背景大字，记为 `decor` 不触发重叠）、`tag`（药丸眉标）、`rotate`（全元素倾斜，elements.js 各原语转发 `rotate`）；② `ARCHETYPES` 扩到 9 种：hero-poster / **magazine** / sidebar-split / **numbered** / bento / **bigquote** / comparison / card-grid / **asymmetric**。

---

## 第十轮：ghost 变淡 + 并列块填色一致（2 个问题）

### 问题 10.1 — 大字覆盖（ghost 太显眼盖住内容）
**根因**：ghost 之前不强制变淡——实色调 + 超大字号（出现 360pt "03"）压住正文。
**方案**：`color.lighten(fill, 0.72)` 把 ghost 颜色（无论 LLM 给什么）往白混 72%；字号封顶 200pt。视觉确认 p4 四个 "01-04" ghost 现在是淡淡背景，不盖内容。

### 问题 10.2 — 并列框填色不一致（有的白底有的填色）
**方案**：`detectInconsistentBlocks` 特征签名加入**填色类别**（`color.fillCategory`：light/dark/accent，palette 键有映射）——同一行并列大块填色类别不同（如两白底+一深底）即报错；composer 要求"并列块填色相同，不要一个白底一个深色/彩色底"。最终 deck 所有并列块填色一致（0 混搭）。

---

## 第十一轮：空白检测 harness（agentic：工具 + LLM 代理）

### 问题 11 — 需要一个独立的留白检测，能"标注出具体的空白矩形框"，且真正做成"harness 提供工具、LLM 决定用不用"的 agentic 形态
**方案**：独立的 `blankcheck.js` + `lib/blank-detect.js`，配合新增的 `lib/llm.js::agent`（工具调用循环）。
- **架构**：harness 当"眼睛/工具箱"，文本大模型当"大脑/代理"——**不是固定流水线，而是 LLM 按需调工具**。
- **harness 提供的工具**（坐标全部由 harness 精确测量，LLM 不凭空报坐标）：
  - `list_slides` / `measure_page` / `find_empty_regions`（迭代最大空白矩形，英寸精确）/ `find_thin_blocks`（框大字少）/ `draw_red_box`（给确认留白画红框到 PNG）/ `finish`（提交）。
- **LLM 代理自主决定流程**：`list_slides → 对各内容页测量 → 判断 → 对真留白 draw_red_box → finish`；封面/结语刻意留白由 LLM 据标准排除。
- **输出**：每页确认的空白矩形（精确坐标 + severity + 理由）+ 红框画到 slide PNG（`<deckDir>/blankcheck/`）**供人工核对**（对接师兄说的"标注出框→人检验→通过率"闭环）。
- `--no-llm` 只出几何候选；`--save report.json` 存结构化报告。
- 数据：优先 `<deck>.layout.json`（build 捕获的 box）+ `.spec.json`（页面角色）；都没有则 python-pptx 从任意 pptx 抽取（fallback）。
- **附带修复**：发现并修了 `layout-qa` 隐性 bug——整页背景色 `bg` 被算作"填满"，导致生产链路留白检测一直被掩盖；已移出 fillLayers（修复后 sparse 页 50% 留白被正确检出）。
**验证**：稀疏测试页 → 代理自主调 7 次工具、画出 2 个红框（52% 高危 + 13% 中危，坐标精确）；密集真实 deck → 代理逐页检查、判 0 留白（不误报）。

## QA 检测器清单（`lib/review.js`）

所有检测器都在 `buildWithReview` 每轮跑，与 layout-qa 报告合并喂给 `reviseFree`：

| 检测器 | 触发条件 |
|---|---|
| `detectStatTiles` | 一页 ≥2 个"大数字+一句话"方格 |
| `detectTooManyBlocks` | 非列举页大块面（≥2.5in²）>3 |
| `detectHiddenImages` | 图片被其后不透明方框覆盖 ≥60% |
| `detectThinBlocks` | 大块内文字估算填充 <50%（框内留白） |
| `detectInconsistentBlocks` | 同行并列块视觉（图/图标）或**填色**不一致 |
| `detectImageLight` | 内容页 0 图；或并列块图片数 < 块数 |
| `countOverlaps`（护栏） | 修订后重叠数变多 → 拒绝修订、保留原元素 |

## 使用

```bash
node chat.js
ppt> 做一个下一代显示技术的 ppt，创意版式     # 自由版式：微软雅黑 + 多样构图 + 图文并茂 + 全套校验
ppt> 做一个量子计算的 ppt                      # typed 路径（也自带版式校验 + 去重）
ppt> /help                                     # 查看全部命令
```

每份 deck 落盘 `.pptx` + `.spec.json` + `.brief.json` / `.outline.json` / `.slides.json` / `.layout.json`，生成过程完全可追溯。
